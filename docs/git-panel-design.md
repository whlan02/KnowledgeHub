# Git 面板设计(调研结论 + 实施计划)

## 调研来源
- VS Code 源代码管理:<https://code.visualstudio.com/docs/sourcecontrol/overview>、<https://code.visualstudio.com/docs/sourcecontrol/history>
- GitHub Desktop 的 History / 分支下拉:<https://docs.github.com/en/desktop>
- Obsidian Git 插件(同类产品,笔记 + Git):<https://github.com/vinzent03/obsidian-git>
- 提交说明惯例(摘要 50 字符、正文 72 字符,GitLab / SourceTree 的字数提示需求)

## 行业标准的元素
1. **变更列表分区**:"已暂存"和"未暂存"两组;每个文件一行,带状态字母/颜色(M/A/D/R/U)。悬停出现 `+`(暂存)、`−`(取消暂存)、`↶`(放弃)按钮;支持右键菜单与拖拽。
2. **列表/树两种视图**切换,以及按文件名过滤。
3. **差异视图**:点文件打开;并排或行内两种;增删行着色;能按块(hunk)暂存。
4. **提交输入框**:摘要 + 描述两栏;摘要超过 50 字符高亮溢出部分;`Ctrl+Enter` 提交;提交按钮显示已暂存文件数;可勾选"修改上一次提交(amend)"。
5. **历史**:提交列表(摘要、作者、相对时间、短 hash),点开看该次提交改了哪些文件及差异;可看单个文件的历史;"恢复到此版本"。
6. **分支**:状态栏上的分支名可点,下拉里搜索、切换、新建;有未提交改动时切换要提示。
7. **同步状态**:领先/落后提交数(↑2 ↓1)、最近同步时间、同步按钮(拉取/推送——需用户批准后才做)。
8. **编辑器内线索**:文件树里带改动标记的小圆点;编辑器边栏标出新增/修改/删除的行。
9. **安全**:放弃改动必须确认(并说明不可恢复);危险操作默认不选中;错误信息原样显示并可复制。
10. **空状态与未初始化**:非仓库时给"初始化仓库"入口;无改动时显示"已是最新"。

## 对本应用的取舍
笔记是 Markdown,不是代码,所以:
- 差异视图默认用**行内**对比(窄面板更好读),并排留作可选。
- 按块暂存放后面;先做按文件暂存。
- 编辑器边栏标记行变化放最后。
- 推送/拉取/同步状态:**等用户批准**才做。

## 实施顺序(每步带测试,做完提交)
1. 后端:`git_diff(path)`、`git_stage / git_unstage(paths)`、`git_log(path?, limit)`、`git_show(commit)`、`git_branches / git_checkout / git_create_branch`、`git_init`、`git_restore(path)`(放弃,前端需确认)。
2. 文件树改动标记。
3. 侧边"源代码管理"面板:分区列表 + 暂存/取消暂存/放弃 + 提交框(摘要/描述/字数提示/Ctrl+Enter/amend)。
4. 差异视图。
5. 历史视图(含单文件历史)与恢复到某版本。
6. 分支下拉。
7. 未初始化的空状态与初始化按钮。
8. (待批准)领先/落后、拉取、推送。
